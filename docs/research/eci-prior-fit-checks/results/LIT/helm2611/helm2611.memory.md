## Canonical Facts

### Problem and estimand

- A model is a random map f: Q -> X from queries to responses. A task t is a query set Q^(t) of size M^(t) plus a scoring function s^(t). The estimand is the true full-task score y_i^(t) = s^(t)(f_i, Q^(t)), a nonnegative real (tex:187-193). Scores are assumed to be means of bounded per-query scores (Assumption 1, tex:1030-1033).
- Observed data are (model, task, query) triples. Q_i^(t) is the observed query subset, m_i^(t) its size, and the sample score is s^(t)(f_i, Q_i^(t)) (tex:195-202).
- "Sparse" = few models with m_i^(t) > 0 on a task. "Unpaired" = small cross-model query intersections; rho_ii'^(t) = m_ii'^(t) / m_i^(t) (tex:204-209).
- Two prediction tasks are treated as regimes of m_i^(t): query-efficient evaluation (m > 0) and (model, task) score completion (m = 0) (tex:213-224).

### Model: Product Kernel Perspective Space (PKPS)

- Inputs: embedded queries u_j = g_Q(q_j), embedded responses x_ij = g_R(f_i(q_j)), a query kernel k_Q >= 0 and a response kernel k_R >= 0 (tex:233-243).
- Affinity (Eq. 1): A_ii' = sum_{j in Q_i} sum_{l in Q_i'} k_Q(u_j,u_l) k_R(x_ij, x_i'l) / sum_{j,l} k_Q(u_j,u_l). Each entry is normalised by its own query-kernel mass (tex:244-250).
- Dissimilarity D^2_ii' = A_ii + A_i'i' - 2 A_ii'. Classical MDS: B = -1/2 J D^2 J, top-d eigenpairs with negative eigenvalues floored at zero give the representation psi-hat_i in R^d (Eq. 2, tex:251-267).
- DKPS is the special case k_Q(u,u') = 1{u = u'}; any strictly positive k_Q makes Eq. 1 defined whenever both models have at least one query (tex:269-273).
- Prediction: embed all n+1 models jointly (Eq. 1 uses no scores, so the target is embedded with the references), fit a regressor h^(t): R^d -> Y on (psi-hat_i, sample score_i^(t)), predict h^(t)(psi-hat_0) (tex:351-356).
- Completion uses the same machinery: a model with no responses on task t is embedded from its responses on other tasks, and the regression transfers scores of reference models that were evaluated on t (tex:424-427).
- There is no likelihood, no noise model, no link function for the score, and no priors in PKPS. It is a kernel-MDS embedding followed by a nonparametric regressor. [inferred from tex:226-356]

### Implementation used in the experiments

- Embeddings: `gemini-embedding-001`, 3072-d, for both queries and responses (tex:477-479, tex:772-773). Single-token answers (MedQA, LegalBench) are replaced by the option text or class name before embedding (tex:773-777).
- PCA: one shared query space capped at 64 components; one shared response space whose dimension equals the sum of per-dataset second Zhu-Ghodsi elbows (at most 48 each; 92 on HELM, 83 on EEE); response vectors unit-normalised; PCA fit on observed rows only (tex:778-784, tex:886-888).
- Kernels: RBF on queries, linear on responses for real data (RBF on synthetic). One sampled response per (model, query) (tex:786-791).
- Query bandwidth: chosen per run by leave-one-model-out K-NN (K = 8) on observed scores over sigma in {0.03, 0.1, 0.3, 1, 3} x median pairwise query distance, plus the near-delta DKPS limit (tex:786-790).
- MDS dimension d = 8 "following Helm et al. 2026 and fixed a priori" (d = latent dimension 5 on synthetic) (tex:793-796). No data-driven rank selection.
- Regressor: distance-weighted K-NN with K = 5, fit leave-one-family-out (tex:798-801).
- Query-efficiency targets are reference models' full-task scores. Completion targets are residuals after logit transform, per-task standardisation to unit variance and a two-way (model + task) additive bias, the same pipeline as the LRMC baseline (tex:802-809).

### Baselines

- LRMC "follows BenchPress": logit space, per-task standardisation, two-way bias, rank-2 ALS with ridge lambda = 0.1, averaged over 5 random initialisations; cross-fit on observed cells (tex:811-814). Rank 2 and lambda are inherited, not re-tuned on these suites. [inferred]
- IRT: 1PL (Rasch) on binary tasks; item difficulties by ML (L-BFGS) on the largest fully observed (model x item) block; per-model ability by bounded scalar MLE clipped to [-4, 4] (tex:814-817). Excludes WMT on HELM; applies to all EEE tasks (tex:894).
- Sample score: the cell's own m-query mean (tex:817).
- DKPS: paired version from Helm, Johnson, Priebe (arXiv 2605.07096) (tex:487).
- Ensembles: query-efficiency = alpha * sample + (1 - alpha) * PKPS with alpha per held-out family on a 21-point grid by leave-one-family-out validation; completion = PKPS blended with LRMC with a weight fit by held-out cross-validation on observed scores (tex:819-824).

### Theory

- Theorem 1 (concentration): under bounded kernels and responses, cross-model query-kernel mass kappa = inf E[k_Q(u,u')] > 0, and an eigengap after the d-th eigenvalue of the population B*, with every model having at least m queries, max_i ||psi-hat_i - W psi_i|| <= C kappa^-2 lambda_d^-1/2 (1 + beta) n sqrt(log(4 n^2 / delta) / (2m)) with probability 1 - delta (tex:320-329). Constant C = 106 (1 + B_R) B-bar (tex:1177). Note the bound grows linearly in n. [shown: proof at tex:1087-1185]
- Theorem 2 (query efficiency relative to paired DKPS): (i) with a guarded cross-validated bandwidth on a grid containing sigma = 0, MSE(PKPS-CV) <= MSE(DKPS) w.h.p. for large n, at any pairing fraction; (ii) if query designs share no atom (Assumption 5), caches are i.i.d. (Assumption 6) and a fixed-budget eigengap holds (Assumption 7), the gap is at least any c < I_m(sigma*), the score variance explained by the fixed-budget population representation (tex:397-412, tex:1193-1365).
- Part (i) is a selection guarantee (Hoeffding on a validation split plus a guard of 2 tau), not a statement about PKPS geometry (tex:1193-1233). [inferred]
- The theorem's estimator differs from the experimental one: it uses a three-way split (embedding / regression / validation sets), Nystrom out-of-sample extension and a guarded selection rule; experiments embed all models jointly, use leave-one-model-out K-NN for bandwidth and no guard (tex:1194-1219 vs tex:351-356, tex:786-790). [inferred]
- Theorem 2 assumes reference scores are observed exactly (tex:399-400), while the experiments regress on sample scores for completion.
- Transitivity plus Theorem 2 of the DKPS paper gives query efficiency relative to the sample score [claim, tex:420-422]; it relies on an external result not reproduced here.

### Data

- HELM suite: 18 tasks from HELM-Lite (7 MATH subjects, 5 WMT-14 directions, MedQA, 5 LegalBench subsets), 93 models from 20 developers evaluated on all 18; each task capped at 120 queries by seeded subsample; unique-query counts 30 to 1000 (tex:446-451, tex:708-736, Table 2).
- EEE suite: from the Every Eval Ever datastore (Batzner et al., arXiv 2606.14516, dataset `evaleval/EEE_datastore`). Five benchmarks with widest item-level coverage (MATH-MC, GSM-MC, GPQA-Diamond, JudgeBench, RewardBench 2), 45 models from 13 developers present on all five and answering every item, 16 tasks by sub-task split (tex:878-883, Table 3, tex:922-939). Items per task 42 to 1319 (tex:910-917). All scores binary (tex:894).
- EEE store-level facts as of the paper: 36 benchmarks, 165 models, 15% of (model, benchmark) pairs evaluated, median 5 benchmarks per model, 59% of model pairs share no benchmark; 26 of 33 benchmarks with at least two models are essentially fully paired (23 identical item sets), 7 arena-style benchmarks (six Fibble arenas plus Wordle arena) have mean per-pair overlap 0.27 to 0.66 (tex:453-461, tex:868-878).
- Sparsity and unpairedness in both suites are **induced by uniform masking** of a dense matrix, so that true scores exist (tex:451, tex:462-463, tex:662-664). On EEE each cell's observable pool is 32 queries drawn with a model-dependent seed (median rho 0.09, mean 0.18); the target is always the full-depth mean, which is never embedded (tex:888-893).
- Granularity: item level. The method needs raw response text and query text, not only item scores (tex:233-235, tex:469-470).
- Synthetic: latent dimension 5, embedding dimension 20, scores v_i . t_k + noise, queries near task centres; controls rho, p_task, p_query (tex:434-442, tex:847-856).

### Evaluation protocol

- Leave-one-family-out: all models from the target's developer are excluded from the regressor's training set (tex:500-502, tex:798-801). The embedding itself is fit jointly on all models including the target (tex:351-355).
- Metric: MAE of predicted vs true full score on a 0 to 1 scale, per-seed mean over tasks then mean +/- 1 SEM over 16 seeds (50 on synthetic) (tex:503-504, tex:826-827).
- Sweeps: budgets m in {1,2,4,8,16,32}; cohort n in {10,20,40,60,93} (HELM) or {10,20,40,45} (EEE); p_task in {0.2,0.35,0.5,0.7,0.9}; p_query in {0.1,0.25,0.5,0.75,1.0}; task count T in {4,8,12,18} or {4,8,12,16} (tex:826-834).
- Tests: two-sided Wilcoxon signed-rank on per-task mean error differences (18 or 16 tasks), ensemble vs sample at m = 1 and ensemble vs LRMC at p_task = p_query = 0.5 (tex:836-843). No multiplicity correction is mentioned.
- Uncertainty reporting: SEM over seeds only. No predictive intervals, no per-cell uncertainty, no calibration analysis in the paper. [inferred from tex:503-504, tex:826-845]

## Terminology and Conventions

- **PKPS**: Product Kernel Perspective Space, the MDS embedding of models from the product-kernel affinity (tex:253-255).
- **DKPS**: Data Kernel Perspective Space, the paired special case (tex:180, tex:269-271).
- **Perspective**: a model's low-dimensional representation psi_i (tex:1023).
- **Query / task / benchmark**: a query is an item; a task is a scored query set; "benchmark" is used for the source dataset and sub-tasks become tasks (tex:189-191, tex:881-883).
- **Sample score** vs **true score**: m-query mean vs full-task mean (tex:200-202).
- **Cell**: a (model, task) pair.
- **p_task**: fraction of cells observed (task coverage). **p_query**: query depth within an observed cell. **m**: per-cell query budget. **n**: cohort size (number of reference models). **rho**: pairing fraction (tex:439-442, tex:117-124).
- **Leave-one-family-out**: exclude all models from the target's developer (tex:500-501).
- **Query-efficient relative to**: Definition 1, eventual MSE dominance with strictness at one n (tex:376-383).
- **LRMC**: low-rank matrix completion as specified by BenchPress (tex:491-492, tex:811).
- **kappa**: cross-model query-kernel mass; **I_m(sigma)**: score variance explained by the fixed-budget representation (tex:316-319, tex:1075).
- **Collection / setup** [space]: a reporting organisation plus harness and protocol; estimates are conditional on a setup (space:README.md "Setups").

## Workflows and Decision Rules

- Paper's suggested deployment: (i) keep cached responses (optionally per-response scores); (ii) fit PKPS on the cache; (iii) regress in the perspective space, optionally ensembled with the sample score (tex:645-651).
- When PKPS helps most per the reported results: small query budgets, small cohorts, low task coverage, rich free-text responses (tex:566-568, tex:577-584).
- When it stops helping: as m grows the sample score's noise falls below the representation's residual bias and overtakes PKPS (tex:550-551); at full cohort on HELM the completion gain over LRMC is not significant (tex:585-587).
- Reading rule: all reported errors are under uniform masking of dense matrices with leave-one-family-out; they do not measure performance under the store's real missingness (tex:662-668).

## Constraints and Non-Goals

- Stated limitations: deterministic scoring assumed (LLM-judge scoring not covered); observation assumed uniform while real missingness "correlates with developer, release date, and expected performance"; unpaired monitoring left as future work (tex:653-675).
- Requires item-level response text for the target model on some task; cannot be applied to aggregate-only leaderboards (tex:469-470). [inferred]
- No claim about the rank of the score matrix is made by this paper; rank 2 appears only inside the inherited LRMC baseline. [inferred from tex:811-814]
- Unstated assumptions detected [inferred]:
  - The embedding model captures score-relevant response differences; no ablation over embedders in the paper, and the Space uses a different embedder.
  - Transductive embedding: the target's responses shape the MDS space used for its own prediction. No score leakage, but the "held-out" model is not out-of-sample for the representation.
  - Bandwidth and ensemble weights are selected on observed scores inside each run; the paper states family scores are never used (tex:824), but selection optimism over 16 seeds is not quantified.
  - EEE suite models are 45 models that ran all five benchmarks and answered every item: a selected, dense, cooperative subset.
  - MAE is averaged over tasks with very different item counts (42 to 1319) and equal weight.
  - JudgeBench and RewardBench 2 are judging tasks whose "responses" are rationales; three of five EEE benchmarks are multiple-choice conversions.
  - Theorem 1's bound scales with n and kappa^-2 and is not evaluated numerically; no evidence the bound is non-vacuous at n = 45 or 93.
